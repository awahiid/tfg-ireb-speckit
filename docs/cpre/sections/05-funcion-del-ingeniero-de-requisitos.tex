\section{Funci\'on del ingeniero de requisitos}
El rol de \textit{Requirements Engineer} no siempre coincide con un cargo formal, pero el handbook define con claridad su funci\'on. Una persona act\'ua en este rol cuando elicit\'a, documenta, valida y/o gestiona requisitos como parte de sus responsabilidades, y cuando tiene criterio para definir procesos RE y seleccionar pr\'acticas adecuadas \cite[p.~14]{cpre}.

Las responsabilidades clave son:
\begin{itemize}[leftmargin=1.2em]
  \item tender puentes entre el problema del negocio y las posibles soluciones t\'ecnicas;
  \item promover entendimiento compartido entre stakeholders y equipo t\'ecnico;
  \item aplicar pr\'acticas de calidad sobre requisitos y sus cambios.
\end{itemize}

El handbook tambi\'en remarca que este rol puede estar distribuido entre perfiles como analistas de negocio, product owners, especialistas de aplicaci\'on, ingenieros de sistemas o desarrolladores, y que requiere habilidades blandas (escucha, negociaci\'on, mediaci\'on y empat\'ia) adem\'as de capacidades t\'ecnicas \cite[pp.~14--15]{cpre}.
