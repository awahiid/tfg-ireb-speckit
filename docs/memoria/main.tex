\chapter*{Resumen}

Este trabajo tiene dos objetivos: mapear el flujo de trabajo de \textsc{SpecKit} ---un \emph{toolkit} de c\'odigo abierto para \emph{Spec-Driven Development} (SDD) de GitHub--- contra las actividades y criterios de calidad de un flujo profesional de ingenier\'ia de requisitos (IREB CPRE Foundation Level, ISO/IEC/IEEE~29148, INCOSE); y evaluar si los resultados cambian cuando se alimenta a \textsc{SpecKit} con requisitos formalizados seg\'un IREB en lugar de con texto libre.

El trabajo produce tres artefactos de referencia: una plantilla de formalizaci\'on con 12~atributos (ID, nombre, tipo, descripci\'on formal, fuente, rationale, prioridad, verificaci\'on, estado, versi\'on, dependencias, m\'odulo); una constituci\'on personalizada con nueve principios IREB para el pipeline SDD; y una r\'ubrica de conformidad (SRCI) con seis criterios para evaluar las implementaciones generadas. Estos artefactos se agrupan en un preset instalable denominado \emph{IREB Kit for SpecKit}.

Para validar el trabajo, se construye un corpus de 52~requisitos derivados de \emph{changelogs} de seis proyectos \emph{Open Source} (Appwrite, Authentik, Cal.com, Directus, Medusa, n8n). Cada caso del subconjunto de evaluaci\'on se ejecuta en dos flujos paralelos ---sin y con el kit IREB--- y los resultados se comparan mediante cuatro m\'etricas: generaci\'on exitosa, compilaci\'on, superaci\'on de tests y puntuaci\'on SRCI.

\noindent\textbf{Palabras clave}: \printkeywords.

\chapter*{Abstract}

This work pursues two goals: to map \textsc{SpecKit}'s pipeline ---an open-source Spec-Driven Development toolkit by GitHub--- against the activities and quality criteria of a norm-based requirements engineering workflow (IREB CPRE Foundation Level, ISO/IEC/IEEE~29148, INCOSE); and to evaluate whether the generated output improves when \textsc{SpecKit} receives IREB-formalized requirements instead of raw text.

The work produces three reference artefacts: a 12-attribute formalization template (ID, name, type, formal description, source, rationale, priority, verification, status, version, dependencies, module); a custom constitution with nine IREB principles for the SDD pipeline; and a conformance rubric (SRCI) with six criteria to assess generated implementations. These artefacts are packaged as an installable preset called \emph{IREB Kit for SpecKit}.

For validation, a corpus of 52 requirements is derived from the changelogs of six Open Source projects (Appwrite, Authentik, Cal.com, Directus, Medusa, n8n). Each case in the evaluation subset is run under two parallel flows ---without and with the IREB kit--- and results are compared using four metrics: successful generation, successful build, passing tests, and SRCI score.

\noindent\textbf{Keywords}: Requirements engineering, IREB, SpecKit, Spec-Driven Development, ISO~29148, process mapping, code generation.
