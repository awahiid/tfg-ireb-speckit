### ID

REQ-N8N-31374

### Nombre

Validación de regiones de AWS soportadas

### Tipo

Funcional

### Descripción formal

El sistema deberá validar el valor proporcionado como región de AWS en las credenciales (por ejemplo, `AWS (IAM) account`) antes de construir y enviar cualquier petición HTTP a los servicios de AWS (como S3, Textract, Transcribe) o al servicio STS (para asumir un rol).

La validación debe garantizar que el valor de la región coincida exactamente de forma sensible a mayúsculas y minúsculas con una de las regiones oficiales de AWS soportadas por el sistema (por ejemplo, `us-east-1`, `eu-west-1`). Si se proporciona una región no soportada, vacía o con un formato inválido (incluyendo intentos de Server-Side Request Forgery como `@example.com#` o IPs), el sistema deberá rechazar la petición inmediatamente lanzando un `ApplicationError` con el mensaje "Unsupported AWS region", sin intentar firmar ni enviar la petición de red.

### Fuente

Pull Request #31374 (https://github.com/n8n-io/n8n/pull/31374), Issue #5045 (NODE-5045)

### Rationale

Anteriormente, el sistema interpolaba el valor de la región directamente en la URL del endpoint (ej: `https://{service}.{region}.amazonaws.com`) sin validación. Si un usuario (o una expresión dinámica) proporcionaba un valor malicioso, podía provocar un comportamiento de Server-Side Request Forgery (SSRF), dirigiendo la petición HTTP firmada a un servidor controlado por un atacante. Validar la región contra una lista estricta de valores conocidos mitiga esta vulnerabilidad.

### Prioridad

Alta

### Verificación

1.  **Región válida**:
    a. Configurar un nodo de AWS (ej. S3, Textract o Transcribe).
    b. Utilizar una credencial de AWS donde la región esté configurada con un valor válido (ej. `us-east-1`).
    c. Ejecutar el nodo.
    d. Verificar que la petición se construye y envía correctamente (pueden ocurrir errores de AWS si las credenciales son inválidas, pero no un error de región no soportada).

2.  **Región inválida**:
    a. Configurar el mismo nodo.
    b. Modificar la credencial para usar una expresión dinámica en el campo de la región (o modificar la credencial directamente si es posible) y establecerla a un valor inválido como `invalid-region`, `@example.com#`, ` us-east-1 ` o vacía.
    c. Ejecutar el nodo.
    d. Verificar que el nodo falla inmediatamente con un error de aplicación que indica "Unsupported AWS region".
    e. (Opcional, si hay acceso a logs de red o debug): Confirmar que no se generó ninguna petición HTTP saliente hacia el endpoint malicioso.

3.  **Flujo STS (Assume Role)**:
    a. Si el sistema soporta la asunción de roles, configurar una credencial que utilice `Assume Role`.
    b. Establecer la región a un valor inválido.
    c. Ejecutar un nodo que utilice dicha credencial.
    d. Verificar que falla con el mismo error "Unsupported AWS region" antes de intentar contactar con el servicio STS.
