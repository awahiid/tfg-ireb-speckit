### ID

REQ-N8N-31371

### Nombre

Validar el tipo de valor de la clave de actualización en el nodo MongoDB

### Tipo

Funcional

### Descripción formal

El sistema deberá validar el tipo de dato del valor proporcionado para la `updateKey` en el nodo de MongoDB para las operaciones `Find And Replace`, `Find And Update` y `Update`. El sistema deberá requerir que el valor sea de un tipo escalar primitivo, permitiendo únicamente `string`, `number`, `boolean`, `bigint`, `null` o `Date`.

Si el valor de la `updateKey` es de un tipo no permitido (como un objeto o un array), el sistema deberá:
1.  Rechazar la operación para ese ítem.
2.  Lanzar un error `NodeOperationError` con un mensaje claro que indique que el valor debe ser escalar (por ejemplo, "The value of '[updateKey]' must be a string, number, boolean, or date").
3.  Si la opción "Continue On Fail" está activada, el sistema deberá emitir un ítem de error con el mensaje correspondiente en lugar de detener la ejecución del flujo de trabajo.

### Fuente

Pull Request #31371 (https://github.com/n8n-io/n8n/pull/31371)

### Rationale

Anteriormente, el nodo de MongoDB no validaba el tipo de valor de la `updateKey`. Permitir valores no escalares, como objetos (que podrían interpretarse como operadores de consulta de MongoDB, por ejemplo, `{ "$regex": "..." }`) o arrays, podía llevar a comportamientos inesperados o errores poco claros por parte del driver de la base de datos. Esta validación asegura que solo se utilicen valores simples y directos para la identificación de documentos, mejorando la robustez y previsibilidad del nodo y proporcionando mensajes de error claros al usuario cuando la entrada es inválida.

### Prioridad

Media

### Verificación

1.  **Valor de `updateKey` válido (escalar)**:
    a. Configurar un nodo de MongoDB con la operación `Find And Update`.
    b. Proporcionar un ítem de entrada donde el campo especificado como `updateKey` tenga un valor de tipo `string`, `number` o `boolean`.
    c. Verificar que la operación se ejecuta correctamente.

2.  **Valor de `updateKey` inválido (objeto)**:
    a. Configurar el mismo nodo.
    b. Proporcionar un ítem de entrada donde el campo `updateKey` contenga un objeto (p. ej., `{ "id": { "$gt": 5 } }`).
    c. Desactivar "Continue On Fail".
    d. Ejecutar el nodo y verificar que la ejecución falla con un `NodeOperationError` que contenga el mensaje de error de validación especificado.

3.  **Valor de `updateKey` inválido con "Continue On Fail"**:
    a. Repetir el paso anterior, pero con la opción "Continue On Fail" activada.
    b. Ejecutar el nodo y verificar que la salida contiene un ítem de error con el mensaje de validación y que el flujo de trabajo no se detiene.

4.  **Valor de `updateKey` inválido (array)**:
    a. Repetir los pasos 2 y 3, pero esta vez con un array como valor para el campo `updateKey` (p. ej., `{ "id": [1, 2] }`).
    b. Verificar que el comportamiento es el mismo que con el objeto.
