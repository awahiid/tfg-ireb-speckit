# IREB Quality Checklist

> **Purpose**: Generated by `/speckit.checklist`
> **Governed by**: constitution Article 0 (Proportionality First)

---

## Application Tier

**Choose the tier based on change size BEFORE applying criteria.**

| Tier | Change size | Criteria to apply |
|---|---|---|
| **L1 — Minimal** | Trivial (1 file, <20 LOC) | R7, R9, R13 only |
| **L2 — Core** | Small (1–2 files) | R1, R3, R5, R6, R7, R8, R9, R13 |
| **L3 — Full** | Medium+ (2+ files) | All criteria (R1–R13) |

---

## Criteria

### R1. Unique ID
`REQ-[DOMAIN]-[NNN]` format. No duplicates, no reuse.

- [ ] All IDs follow the pattern
- [ ] No duplicate IDs

### R2. Valid Classification
Type is one of: Functional, Quality, Constraint.

- [ ] Type field is non-empty and valid

### R3. Traceable Source
Source documents origin (document type, version/date, identifier).

- [ ] Non-empty Source field
- [ ] Not generic ("various sources", "team discussion")

### R4. Assigned Priority
Priority is one of: High, Medium, Low.

- [ ] Non-empty Priority field with valid value

### R5. Formal Structure
Description starts with "The system shall" + verb + object.

- [ ] All descriptions follow the pattern

### R6. Single Obligation
Exactly one action verb per requirement.

- [ ] No "and" chaining two independent actions

### R7. Observable Verb ← BLOCKING
Verb describes observable behavior. Valid: generate, register, reject, return,
prevent, notify, calculate, validate, block, store, send, redirect, transform,
log, encrypt, hash, render, delete, create, update.

Invalid: manage, handle, process, support, facilitate, improve, provide, enable, ensure.

- [ ] Main verb is observable

### R8. No Critical Ambiguity
No subjective terms: fast, efficient, intuitive, adequate, appropriate,
sufficient, user-friendly, robust, reliable.

- [ ] No ambiguous terms present
- [ ] Quantitative criteria used where applicable

### R9. Observable Verification ← BLOCKING
Verification criterion describes observable behavior (API response, state change,
log entry, event), not intention.

- [ ] Non-empty Verification field
- [ ] Not circular ("will be tested during QA")

### R10. Self-Sufficiency
Requirement is understandable without cross-references.

- [ ] No "see above", "as described in previous step"

### R13. No Hallucinated Context ← BLOCKING
Source, Rationale, and stakeholders are limited to what appears in the input.
No invented stakeholders, objectives, issues, or PRs.

- [ ] Source references only what's in the input
- [ ] No invented stakeholders or business context
- [ ] No invented issue/PR numbers

> ⚠️ R13 is BLOCKING: fail → rewrite requirement regardless of other scores.
