### ID

REQ-N8N-31507

### Nombre

Ocultar controles de conexión para credenciales privadas sin permiso de actualización

### Tipo

Funcional

### Descripción formal

El sistema deberá ocultar el botón "Connect" (en la tarjeta de credenciales) y el enlace "Connect" (en la vista de detalles del nodo) para aquellas credenciales privadas (resolvibles) que no estén conectadas, si el usuario actual carece del permiso `credential:update` sobre dicha credencial. El aviso informativo que indica que la credencial no está conectada ("not connected yet") deberá seguir mostrándose. La acción "Disconnect" deberá permanecer visible y accesible independientemente del permiso de actualización, siempre y cuando la credencial esté conectada por el usuario.

### Fuente

Pull Request #31507 (https://github.com/n8n-io/n8n/pull/31507)

### Rationale

Anteriormente, los usuarios con permisos de solo lectura (`credential:read`), como los espectadores de un proyecto (`project:viewer`), podían ver y hacer clic en los controles para conectar una credencial privada no conectada. Sin embargo, esta acción fallaba en el servidor porque los endpoints de OAuth requieren permisos de actualización (`credential:update`). Este cambio mejora la experiencia de usuario ocultando controles que no pueden utilizarse y evita errores derivados de acciones no autorizadas en el frontend.

### Prioridad

Media

### Verificación

1.  **Usuario con permisos de solo lectura**:
    a. Autenticarse como un usuario con rol de visor de proyecto (`project:viewer`), que solo tenga permiso `credential:read` sobre una credencial privada no conectada.
    b. Navegar a la lista de credenciales y observar la tarjeta de dicha credencial. Verificar que el botón "Connect" no es visible, pero sí el aviso "not connected yet".
    c. Abrir un nodo que utilice esa misma credencial privada no conectada. Verificar que el enlace "Connect" no es visible en la vista de detalles del nodo, pero el texto "Your account isn't connected yet" sí lo es.

2.  **Usuario con permisos de actualización**:
    a. Autenticarse como un usuario con rol de propietario o editor, que posea el permiso `credential:update` sobre una credencial privada no conectada.
    b. Verificar que tanto el botón "Connect" en la tarjeta de la credencial como el enlace "Connect" en el nodo correspondiente son visibles y funcionales.

3.  **Acción de desconexión**:
    a. Autenticarse como un usuario que ha conectado previamente una credencial privada (incluso si sus permisos actuales se redujeran a solo lectura, aunque este escenario pueda ser raro, el código lo permite explícitamente).
    b. Verificar que la acción "Disconnect" sigue estando disponible y es funcional para la conexión que pertenece a dicho usuario.
