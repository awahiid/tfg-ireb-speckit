### ID

REQ-N8N-31349

### Nombre

Control de acceso basado en permisos para endpoints de control de versiones

### Tipo

Funcional

### Descripción formal

El sistema deberá restringir el acceso y la exposición de datos en los endpoints de control de versiones (`source control`) basándose en los permisos del usuario autenticado, de la siguiente manera:

1.  **Endpoint de Preferencias (`GET /preferences`)**:
    *   **Administradores Globales**: Para usuarios con el permiso global `sourceControl:manage`, el sistema deberá devolver el objeto de preferencias completo, incluyendo propiedades sensibles como `repositoryUrl` y `publicKey`.
    *   **Usuarios Autorizados en Proyectos**: Para usuarios que tienen acceso a al menos un proyecto gestionado por el control de versiones (pero sin el permiso global), el sistema deberá devolver un subconjunto de las preferencias que excluye datos sensibles. La respuesta incluirá `connected`, `branchName`, `branchColor` y `branchReadOnly`.
    *   **Otros Usuarios**: Para el resto de los usuarios, el sistema deberá devolver un objeto mínimo que contenga únicamente la propiedad `branchReadOnly`.

2.  **Endpoint de Ramas (`GET /get-branches`)**: El sistema deberá restringir el acceso a este endpoint únicamente a usuarios que posean el permiso global `sourceControl:manage`.

3.  **Endpoint de Estado de Sincronización (`GET /get-status`)**: Si la petición se realiza con `direction: 'push'`, el sistema deberá requerir que el usuario tenga el permiso `sourceControl:push` (ya sea global o a nivel de proyecto).

### Fuente

Pull Request #31349 (https://github.com/n8n-io/n8n/pull/31349)

### Rationale

La implementación anterior exponía propiedades de configuración del control de versiones, algunas de ellas sensibles, a todos los usuarios, independientemente de sus permisos. Este requisito busca mitigar ese riesgo de seguridad, asegurando que los usuarios solo puedan ver la información y acceder a las funcionalidades para las que están explícitamente autorizados, siguiendo el principio de mínimo privilegio.

### Prioridad

Alta

### Verificación

1.  **Acceso a Preferencias como Administrador**:
    a. Autenticarse como un usuario con el permiso `sourceControl:manage`.
    b. Realizar una petición a `GET /source-control/preferences`.
    c. Verificar que la respuesta contiene el objeto de preferencias completo, incluyendo `repositoryUrl` y `publicKey`.

2.  **Acceso a Preferencias como Usuario de Proyecto**:
    a. Autenticarse como un usuario sin permisos globales, pero con acceso a un proyecto bajo control de versiones.
    b. Realizar una petición a `GET /source-control/preferences`.
    c. Verificar que la respuesta contiene `branchName` y `branchColor`, pero no `repositoryUrl` ni `publicKey`.

3.  **Acceso a Preferencias como Usuario Básico**:
    a. Autenticarse como un usuario sin permisos de control de versiones.
    b. Realizar una petición a `GET /source-control/preferences`.
    c. Verificar que la respuesta contiene únicamente el campo `branchReadOnly`.

4.  **Acceso a Ramas**:
    a. Autenticarse como un usuario sin el permiso `sourceControl:manage`.
    b. Intentar realizar una petición a `GET /source-control/get-branches`.
    c. Verificar que la API devuelve un error de tipo `403 Forbidden`.
